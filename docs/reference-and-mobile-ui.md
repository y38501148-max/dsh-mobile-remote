# 手机界面与连接诊断

## 参考项目

参考 [liguobao/ds-harness-remote](https://github.com/liguobao/ds-harness-remote/tree/8397b7397627b1017000615175acf36191dfea73) 的网络和 Android 交互设计。本次没有复制其实现，也没有默认接入它的托管服务。

该项目的 Host 和 Client 都主动连接协调服务器，经 WebRTC 尝试 LAN/P2P，再退到 TURN 或加密 WebSocket Relay。所有路径承载 Noise 加密的业务消息。因此它不要求校园网开放电脑的入站端口，但仍依赖可达的协调及中继服务。服务端运行代码不在该插件仓库内。

其当前业务接口面向 Harness v0.1.1 rc.2 / v0.1.2，与这里已经验证的 v0.1.0 rc.6 并非同一协议代际。本插件继续使用当前 Host 原生协议、草稿与权限系统，不升级或替换用户的 Host。

## 本轮实现

- 手机单独使用「对话 / 会话 / 设置」导航；桌面保留原界面。
- 会话列表按更新时间排列，可搜索标题和目录，筛选进行中及待确认任务；归档、子代理和未选中的空白会话不混入列表。
- 工作区单独选择，创建会话仍调用 Harness 的工作区服务。
- 对话单栏显示，详情占满手机宽度，模型、权限、附件和发送保留真实原生操作。
- 键盘显示时收起底部导航；切换手机页面保留当前草稿。返回键先关闭当前手机页面，再返回电脑列表。
- 原生电脑菜单提供任务提醒、重连、管理和连接诊断。

消息渲染及工具、审批、草稿等业务能力继续由 Host 客户端提供；移动端导航和布局独立呈现。这样不需要再维护一套会话协议或丢失已安装插件的消息类型。

## 先排查直连

当前没有部署公网中继，也没有自动 P2P 穿透或 Cloudflare 回退。连接诊断只检查用户选中的电脑，不向公共检测服务发送地址或授权。

1. 电脑保持 Harness 运行，确认「设置 → 手机远程」的入口已开启。
2. 手机先连接同一 Wi-Fi，在 App 电脑卡片或右上角菜单选择「连接诊断」。
3. 记录手机网络、IPv6、电脑端口及身份校验结果。
4. 关闭手机 Wi-Fi，使用移动数据再诊断一次。

| 诊断结果 | 下一步 |
| --- | --- |
| 手机没有网络 | 先连接 Wi-Fi 或开启移动数据 |
| 未检测到 IPv6，电脑使用 IPv6 地址 | 换一个支持 IPv6 的网络；VPN 可能需要单独检查路由 |
| 电脑端口未连通 | 检查电脑是否休眠、入口是否开启、地址是否变化；同网与移动数据都应分别测试 |
| 同网可达，移动数据超时 | 优先排查校园网入站规则及跨网路由，不能仅凭超时断言具体原因 |
| 端口可达，身份校验失败 | 核对电脑二维码、地址和系统时间，不跳过证书验证 |
| 身份与插件均通过 | 此刻、此网络下已能到达电脑，再继续配对或会话 |

如果确认外部入站被限制，需要允许入站的网络配置，或双方主动连接的中继/组网方案。二维码、公钥固定和 UI 改动都不能代替网络可达性。
